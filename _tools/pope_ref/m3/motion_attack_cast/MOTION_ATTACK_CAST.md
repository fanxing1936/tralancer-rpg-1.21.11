# M3：attack / summon / cast 原帧与数值姿态研究

本目录是动作制作的输入与证据，不是最终动画事实来源。最终动画以 `../../pope.bbmodel` 为准；本脚本没有修改它，也没有操作 Blockbench。所有欧拉、深度与幅度都是由二维图像约束重建的起始解，必须经原生模型同帧并排校正，不能称为原游戏骨骼曲线。

## 坐标、骨架与相机

- Java +Y向上，正脸−Z；角色左侧−X，左手持杖。最终层级为 body→left_arm→left_hand→staff→staff_glow。
- right_arm rest Z=−48°，head rest Z=8°。`rotation`是增量，`world_rotation`是作者阶段的世界欧拉约束；运行时仍应解算为纯数字局部rotation/position。
- crown必须反向补偿head俯仰。attack f13头盒下俯而冠轴近竖直，不可锁定crown相对head不动。
- cape上端pivot为(0,12,2.2)，下摆向−Y。负X旋转使下摆甩向背后+Z；正X使它卷向身体前方。
- 三GIF均500×500，但人物缩放不同。相机拟合见camera_calibration.json。6个头角采用最终12×7×6头盒与rest Z=8°，测量误差与原作比例差异仍可能混入相机参数。

## 关键观察

### attack：一次前压，前10→11帧变化极快

- f0→f7（0–0.28s）：左手举杖向后上，右臂横伸，角色右腿向前踢。
- f10→f11（0.40–0.44s）：杆轴从近竖直迅速变为向前横压。不能用全段平滑缓入抹掉这40ms的突变；20TPS无法逐帧等时复现，必须在0.40/0.45s附近保留姿态。
- f13–18（0.52–0.72s）：躯干强烈前压，杖端向前下，冠轴仍近竖直。f23起收回，f31回首姿。
- 原图只有一遍准备→伸杖→回收，不能做三次挥杖来假装三连弹。

握点变化有明确像素证据：f0杆底(306,390)、托盘(307,255)、握点(306,303)，握点位于杆底→托盘约64.4%；f7为(309,306)→(393,179)，握点(330,274)，约25.1%。同一17单位杆对应向上窜约6.7单位。允许staff局部Y约+7，表示手仍贴杆但换握，而不是把手与杆拆开。

### cast：方块离开托盘升高，整杖没有同幅度上升

- f0→f6（0–0.24s）：把杆从身侧带到脸前；杆托盘停在前额/头顶下缘附近。
- f6→f23（0.24–0.92s）：发光立方单独浮起，身体小幅后仰，头冠向画面右倾，后布抬向背后。
- f23–45（0.92–1.80s）：方块在皇冠上方悬停，杆仍在脸前；f51→57方块下降，f62归位。
- f23放大证据见cast23_enlarged.png：灰托盘约(231,220)，方块亮像素质心约(241,88)，其间确有透明空隙。静息托盘约(346,289)，方块质心约(344,250)。轴向估算比首姿额外浮起约8单位。因此staff_glow独立position Y约+8，不能将整根杆上移8单位代替。

## 文件与误差

- action_poses_candidates.json：40个可执行姿态起始解，所有骨骼都有明确数值。body position当前为零；侧向/纵向根位移尚未由二维点解深度，需要根制作者统一IK后调整。
- manual_landmarks.json：人工原像素点、遮挡null、杆轴/换握/悬浮量估计；点误差约3–5px，头盒中心代理误差约4–7px。头中心不是骨骼pivot。
- pixel_tracks_auto.json：146帧颜色区域质心/杆红带PCA；普通红带选择可能误选冠宝石（summon f37就是已知例子），不能把未人工检查的所有自动点直接作为IK约束。
- *_landmarks_*.jpg：原画布测量联系表。H=灰头可见轮廓中心代理、B=杆底、T=托盘、L/R=左握点/右手端、C=亮立方像素质心。没有旋转源图或用渲染图替代原图。
- *_grid_*.jpg：25px网格原帧联系表；*_landmarks_*优先于自动颜色圈。

尚未做：未原生渲染这份起始解、未在真实游戏内看过、未证明最终视觉还原度、未烘焙/集成玩法或音效。root接手原生并排后应以数值像素误差和视觉朝向共同判定，不能因JSON合法就声称动作完成。
