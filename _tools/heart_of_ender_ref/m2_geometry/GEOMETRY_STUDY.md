# M2 静态几何与正交相机研究

本目录是提供给正式 Blockbench 模型的几何规格和投影研究，**不是 `.bbmodel`，不是已通过视觉验收的最终模型**。没有动画、玩法、音效绑定、运行时入口或构建接入。原始参考版权属于 Mojang Studios，本项目非商业，与 Mojang 无关联。

## 可交给 Blockbench 的内容

- [geometry_spec.json](geometry_spec.json)：完整 `bones`、`cubes`、`parts`、相机与推断说明；Java 空间，+y 向上、面向 -z。
- [原渲染与无材质几何并排](reference_fit.png)：相同的1000×840投影画幅。右侧颜色仅区分几何，不能当作最终纹理、发光效果或半透明测试。
- [正面、侧面、背面、三分之四](geometry_four_views.png)：背部及被遮挡的深度均标为推断。正/侧/背视角自动缩放到画幅，不用于比较世界尺度。
- [部件局部边界检查](part_bounds.json)：21 部件全部满足单部件各轴跨度≤48，最大跨度31.5；居中于(8,8,8)后落在−16…32。
- 可复现脚本：`_tools/heart_of_ender_geometry_study.py`。只写本目录；不写正式 `.bbmodel`、图集或共用管线。

## 坐标与层级

立方体的 `from/to` 与骨骼 `pivot` 均为未摆姿态时的**全局模型坐标**，不能把子骨误当成“相对父骨局部坐标”。每骨旋转按 `Rz · Ry · Rx` 围绕 `pivot` 应用，再沿父链组合；与当前 `display_mob.py` 一致。所有立方体自身没有旋转，只有骨骼有 rest 旋转。

`shell_root` 是无几何的统一父骨，静态 Z 倾斜−12°；`inner_root` 保持小人独立层级。下颚是头部的子骨，两个肢段各有自己的骨骼。此根坐标是研究用原点，并不是已校准的游戏地面/骑乘座位原点；规格中 `seat=0` 仅供归一化测量，`model_scale=null`，最终游戏大小仍未选择。

| 构成 | 展示部件数 | 说明 |
|---|---:|---|
| 躯干、上颅、下颚 | 3 | 躯干由4个cube组成，仍是1部件 |
| 六条近、远两段肢体 | 12 | 保留可见折弯；不加手掌、手指或脚掌 |
| 小人头、身、左右臂、左右腿 | 6 | 冠/鼻合入头，短足合入腿 |
| 眼、前牙、侧牙发光骨骼 | 0 额外部件 | 三个空骨由正式模型作者添加采样亮形，刚性合入头/颚 |
| **合计** | **21** | 含发光子骨仍是21个parts |

发光空骨固定为 `shell_eyes_glow`（父骨 `shell_head`）、`shell_teeth_front_glow`、`shell_teeth_side_glow`（父骨 `shell_jaw`）；rest 均为零，已列在 `glow_bones`。本规格未添加白色嘴光大贴片，也没有将44×44 mask二值化或重绘。

## 头部轮廓与相机拟合

M1 的347px头部包围宽是包含低对比背侧相接区的保守图像范围，不能直接当作一个方块的宽。本阶段将低对比相接区与头方块分开；新的头方块投影四角是拟合用的几何假设，不是原游戏UV或骨架数据。

| 面 | 像素四角（按周界） |
|---|---|
| 前面（包含闭口下颚） | (218,211)、(348,262)、(402,439)、(272,388) |
| 顶面 | (218,211)、(346,103)、(476,154)、(348,262) |
| 画面可见侧面 | (348,262)、(476,154)、(530,331)、(402,439) |

图像向右的前面横向轴(130,51)与眼睛亮条方向一致，对应模型 **−x** 方向；上向轴(−54,−177)；向后轴(128,−108)。轮廓明晰点误差较小，黑色内侧边界约有±8–12px不确定性。以头宽12单位作为尺度，解正交投影两行等长且正交的约束，得到闭口总头高14.787021、深12.410508。将总高分为**上颅高12**与**下颚厚2.787021**，是与开口截图结构一致的建模划分，不是原几何解包结果。

| 参数 | 值 |
|---|---|
| 上颅范围 | `[-6,26,-10.8]` 到 `[6,38,1.610508]` |
| 闭口下颚范围 | `[-6,23.212979,-10.8]` 到 `[6,26,1.610508]` |
| 头骨pivot | `[0,25,0]` |
| 下颚铰点候选 | `[0,26,1.610508]`，位于后上缘，属推断 |
| 头骨相对 `shell_root` 的rest旋转XYZ | `[-17.982730,-0.263876,10.477565]` 度 |
| 正交相机 | yaw−45°、elevation25°、roll0°；位于−x、+y、−z侧 |
| 1000×840画幅的像素尺度 | 15.397157 px/模型单位 |
| 相机正交纵向范围 | 54.555527 模型单位 |
| 相机target | `[4.650743,14.320032,4.792726]` |
| 距target80单位时的相机position | `[-46.617768,48.129493,-46.475784]` |
| 模型原点的屏幕offset | `[498.454163,663.281350]` px |

相机与整体rest旋转的分解并不唯一；上面选择便于在Blockbench复现。真正的约束是 `camera.screen_basis_rows`、屏幕尺度、offset与全部骨骼矩阵组合后的投影，不应只输入yaw/pitch而丢掉target和scale。

相机手性已独立检查：`screen_right × screen_up = viewer`；矩阵P的三行是right、down、viewer，因此det(P)=−1是正确的屏幕y向下约定。没有使用负缩放或把渲染图水平翻转。前面是 **north（−z）**，其图片TL对应模型x=+6、TR对应x=−6；图片可见侧面是 **west（−x）**，不是east。`head_fit.front_model_quad`、`side_model_quad`给出与像素四角一一对应的未摆姿态模型四角。`camera_validation.json`记录手性和重投影检查；保留6位小数后的规格仍只有约0.00018px数值重投影误差，但这不是独立视觉还原度分数。

## 躯干、不透明开口和肢体

躯干外包围为9×31.5×8单位，头后缘与躯干前缘有重叠，避免浮空头和松散肩部。原作下躯干通过半透明/烟雾露出小人；若本管线直接使用完整不透明长方体，会把小人完全遮住。因此本研究采用：上躯干实心、下段保留后壁和窄侧缘、前方开口。**这是适配不透明渲染的明确推断，不是已核实的原作拓扑。** 所有这些cube仍归同一个body part，不增实体。

模型侧对称根点取x=±4.5、z=4，上/中/下层y分别28、18.5、9；逻辑名left在+x，right在−x。A–F 到这些模型侧/层的对应只是复原假设，已逐条写入规格，不能称为原骨架名称。平面上的末端与折点通过参考像素约束，沿视线方向的深度是推断。

| 规格中的侧/层 | 对应参考末端ID（假设） | 近段长度 | 远段长度 | 方截面 |
|---|---|---:|---:|---:|
| left_upper | A | 14.000 | 16 | 4×4 |
| left_middle | B | 16.191 | 16 | 4×4 |
| left_lower | C | 15.257 | 16 | 4×4 |
| right_upper | F | 18.042 | 16 | 4×4 |
| right_middle | E | 17.991 | 16 | 4×4 |
| right_lower | D | 14.000 | 16 | 4×4 |

近段长度不同是单帧投影拟合的结果，不代表原作肢体一定不等长。全段长度相近但未知深度不同的解也可能成立；当前选择保留可见末端和轮廓，并显露背面供审查。每个远端的截面滚转采用保持平整方柱的统一规则，没有额外手腕。没有新增“手掌朝向”的假定。

由于端点直接作为拟合输入，它们的重投影误差接近零**不是独立视觉验证**。真正还需观察的包括柱体粗细、遮挡关系、相接处与侧/背视角是否合理；`reference_fit.png`用于人工比较这些未被端点误差覆盖的部分。

## 小人

小人保留6个独立部件。头顶高条是参考中直接可见的轮廓，其宽高比又与原贴图候选金色4×11×4岛吻合，因此没有把它缩成普通村民的头顶或发髻。头/冠/鼻的尺寸使用原贴图候选比例乘0.35：

| 部件 | 研究尺寸 | 依据和边界 |
|---|---|---|
| 头 | 4.2×2.45×2.1 | 候选12×7×6 UV网；不是原geo |
| 高冠/竖条 | 1.4×3.85×1.4 | 候选4×11×4金色UV岛＋Docile轮廓 |
| 鼻 | 0.7×1.4×0.7 | 候选2×4×2 UV网，部分岛边界不明 |
| 身 | 2.8×3.1×1.75 | 以Docile轮廓为主，兼容UV候选8/9×9×4/5区间 |
| 臂、腿和短足 | 详见cube表 | 原UV蓝金长条的语义未确认；未为迁就15px长岛而强行拉长手臂 |

小人静态整体坐标平移`[0,-4.3,7.4]`已经直接应用到规格中的骨原点和cube坐标，不是需要额外执行一次的变换。其目的是把小人放进下躯干的可见窗口，匹配整体渲染下部亮轮廓；不要在导入时重复加这个offset。

## 验证与后续边界

本脚本已实际运行；21件、局部跨度、零cube自旋转的规格约束通过。正式模型添加发光cube、裁切UV后仍需用正式 `.bbmodel` 再跑校验。这里没有声称已在Blockbench或真实游戏中完成验收，也没有创建动画。没有干净原作正背参考，因此四视图中的背侧只能检查自洽性，不能证明背部已经精确复刻。

如果正式 `.bbmodel` 在Blockbench里又改了几何或姿势，本研究脚本只能重建本目录的研究规格，不能自动重现编辑器之后的修改。后续应以 `.bbmodel` 为事实来源。
