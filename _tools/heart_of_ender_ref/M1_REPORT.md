## 2. 结构测量结论

**能数出六个独立肢体末端，不能套用普通末影人的四肢。** 主渲染、Idle帧及抬身截图相互印证。A–F只是主渲染/Idle起始画面的编号，尚未强行命名为解剖左/右或前/后。

|---|---|---|---|

### 展示实体预算尚未锁定

如果为了保留可能的各肢折点，六肢都设置近/远两段，外壳为头1+颚1+躯干1+肢体12=15；小人若保留头/身/双臂/双腿6个独立部件，总计**21个item_display的候选上限**。这是预算方案，不是已生成数量，也不是六肢两段都已实锤。

16部件方案必须减少独立运动自由度，例如锁定部分肢体关节或合并小人同动部件。发光骨骼可以并入对应的头/颚部件，不额外占实体。不会为了写出“≤16”而暗中做成六根直杆或一张小人贴图；M2前需要确认优先保留动作结构还是严格压到16。

| 最终clip/嵌入动作 | 标注 | 本轮依据与边界 |

| `cross_beam` 外壳 | **推断** | 页面 Cross beam 抬身、由小人发十字光束并顺时针旋转；抬身/laser/ArchBeam截图 |

| `sink` / `rise` | **推断** | 页面 Arch-Visages 描述沉下与再升起；Arch-Visage出入仅作相近运动参照，不当本体原动画。只规划position，不使用scale |

Docile映射：目标时刻 `t` 对应源相位 `u=(0.9*t) mod 4.8`；三周期起点为0、5.333333、10.666667秒。每个源关键姿态 `u_i` 的目标时间为 `cycle_start + u_i/0.9`。目标末端16s闭环回首姿势；不能把三个4.8s周期塞入前14.4s后留1.6s静止。

参考25fps与Minecraft20Hz不是同一个采样网格：4.88s在当前管线会变成98tick=4.90s，增加0.02s；`.bbmodel`仍可保留4.88s来源时长，报告需区分编辑时长与烘焙时长。声音实际cues等到M3/M4姿势确认后登记，不在M1虚构“音效同步已完成”。

**Arch-Visage眼睛区别：** 静态渲染有眼；游戏内GIF出现初期（例如0.20s）也可见眼睛，持续开口阶段则不可见。不能把整个游戏内片段简单称为无眼，也不能照搬未采用版的持续眼睛效果。详细显隐时间以逐帧研究为准。

## 4. 材质决策与取样

参见 [TEXTURES.md](analysis_texture/TEXTURES.md)：已登记6个128×128星空候选窗口、HE左右眼/牙齿及AV嘴部的原图矩形，并保留最近邻裁片。候选窗口不是最终UV；M2会把每个面的来源与图集坐标对应起来。

- 711图为RGB星点原图，渲染图星点呈紫色；原小人纹理为灰/蓝/金，GIF呈粉紫发光。原作shader的通道处理未恢复，**当前没有重着色**。若允许保留点位/形状，仅用渲染采样色烘焙材质近似，需要明确确认；否则只裁窗、不改色，并如实展示色差。
- glow44图不是五官；眼睛/牙齿/嘴只能来自渲染取样，发光骨骼独立设置。
- 星空图的840个透明像素并非只在四周：831个在内部，分布于中下部短横条。候选裁窗已避开，6窗透明像素均为0，避免引入杂色/透明条。
- 首版不依赖半透明。透明躯干、肢根渐隐和小人可见性是M2要展示的视觉难点；本轮未实测半透明，不能声称已解决。

## 5. 管线准备与后续验证边界

已通读 `display_mob.py`，并核对两个薄配置、两个geometry生成脚本及 `tower_wraith.bbmodel`。未修改共用管线。

命名预查在 `_tools`、`rpg`、`resourcepack` 与README未发现既有定义：`heart_of_ender / rpg.he / rpg_he`，`arch_visage / rpg.av / rpg_av`；M5接入前还会复查。绑定对象仍待定，只计划新调试召唤入口。

关键约定：一张base64图集、Java空间+y向上/朝-z、显式面UV、部件局部-16..32、只支持数值rotation/position、idle/walk排前、子骨合并后不再有独立动画。仅零旋转或单轴≤45°子骨用于刚性合并，避免管线未充分拒绝的多轴静默错误。骨骼rest角与动画角直接相加，不做Bedrock符号翻转。

独立父骨可组织外壳和小人，不增加展示实体；独立活动的子部件仍各占一个item_display。小人必须跟外壳放在同一clip。沿用晚tick恢复隐身与通用孤儿清理，具体新生成器在M5接入。单次片段结束默认回idle，sink/death最终保持沉地和小人消失需要本任务自己的收尾入口，不能误把孤儿清理当成死亡动画播放。

嘴部/光束挂点：本轮仅给可查的2D来源区域（HE齿口约`[276,351,441,417]`，小人发光轮廓`[487,555,575,731]`；AV口见贴图研究）。**尚无模型，故不编造Java模型坐标。** M2静态几何确认后登记嘴中心、前向向量和小人十字光束中心的模型空间坐标；M5报告提供随骨骼变换的使用方法。光束、弹体、拖痕、光环均不生成。

本轮未运行 `_tools/rp_build.sh`、`_tools/build.sh`、`rp_validate.py` 或 `server_test.py`：没有模型/生成器可供接入，按阶段安排保留至M5；不把素材检查等同构建或游戏验证。**未在真实游戏内看过本任务模型。** 已看的游戏图和视频均是原作参考。没有同步到PCL实例，后续同步前会先询问。
