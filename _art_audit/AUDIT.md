# 美术风格审计报告

> 审计日期：2026-11-02 ｜ 基线：提交 `739098e` 的构建产物（`rpg/`、`resourcepack/`、`TRALANCER-RPG-图鉴.html`）
> 范围：装备、恶魔生态、契约体系，以及它们涉及的 HUD、粒子和图鉴。
> 对应的规范草案：[`ART-STYLE.md`](../ART-STYLE.md)

## 取证方式

- **文字**：解析 `command/give/*.mcfunction` 中每件物品的 `custom_name` 与 `lore`，用原版 1.21.11 jar 里的 `ascii.png` 和资源索引里的 Unifont 字形逐像素重绘 Tooltip（GUI 缩放 2，底色 `#100010`）。图 01 中左栏是现状的复原，右栏是按规范草案渲染的效果。
- **对比度**：采用 WCAG 相对亮度公式，参照底色为原版 Tooltip 的 `#100010`。可读的门槛是 4.5:1，低于 3:1 视为读不出来。
- **贴图**：对 `textures/item` 下 111 张图逐张检测原生网格（最近邻还原测试）、半透明像素数和色数。
- **颜色清点**：统计产物里出现的文字 Hex 和 `dust` 粒子色，并定位每个颜色在哪个生成器里定义。
- **未做实机截图**：`launch_test.py` 只能启动到标题界面，并且会改写 PCL 实例的 `options.txt`；本会话也没有桌面输入能力去打开背包、悬停物品。图 01 和图 03 是按原版字形与原版规则复原的。下面标注「需实机确认」的条目，在实施后同步到 PCL 实例统一核对。

| 级别 | 含义 |
| --- | --- |
| **S1** | 读不出来：玩家看不清字或看不懂提示 |

## S1 · 读不出来

### S1-1　七柱深色被直接拿来写字　〔图 01、图 02〕

`[DEVIL]`、`[契约]` 前缀和 Lore 中的领主名，都直接用七柱的**身份深色**书写。在 `#100010` 底色上的对比度：

| 领主 | 颜色 | 对比度 |
| --- | --- | --- |
| 路西法 | `#00491C` | **1.91** |
| 贝利尔 | `#5B2C6F` | **1.98**（作者旧色 `#660099`：1.97） |
| 萨麦尔 | `#7B241C` | **2.05** |
| 利维坦 | `#1B4F72` | **2.34**（`[DEVIL]` 用的 `#123E7C`：1.95） |
| 别西卜 | `#5A6B1E` | 3.45 |
| 亚巴顿 | `#6A6A70` | 3.80 |
| 玛门 | `#B7950B` | 7.11 ✓ |

七柱里五柱不达标，其中四柱低于 2:1，几乎是黑字写在黑底上。ENGINEERING §27.7 曾说「罪器的强调色是给 Minecraft 的深色 Tooltip 挑的」，按上表的数值，这个判断不成立。图鉴为此单独加了 `on_dark()` 提亮，游戏内却从没提亮过。

影响范围：7 本七柱契约书的前缀（旧约 `#D4AF37` 与新约 `#62D9E8` 可读，不受影响）；4 件罪器的 `[DEVIL]` 前缀，即路西法、利维坦、萨麦尔、贝利尔（亚巴顿、别西卜仍用 `#999999`，玛门用 `#B7950B`，都可读）；契约 HUD 里的领主名；`polish_demon_names.py` 给七柱 Lore 领主名染的色。产物中这些深色一共出现 488 次。

### S1-2　HUD 招式提示的位图糊成块　〔图 03〕

`build_combat_prompt_font.py --bake` 用微软雅黑粗体在 11px 下渲染，再按 alpha 96 阈值化，以 1 texel / GUI 单位贴进位图字体。结果是：

- 「路西法」「蛇矛破土」「深潮回卷」这类笔画多的字粘成色块，相近的字难以分辨。
- 下层的契约、魔化状态行是原版 Unifont，按 2 texel / GUI 单位渲染。上下两层的字形、粗细和像素尺寸都不一样，看起来像两套 UI 叠在一起。
- **许可风险**：这张位图是用 Windows 自带的微软雅黑（`msyhbd.ttc`）栅格化的，随开源资源包分发，属于字体再分发问题，与 S3-3 的歌词引文是同一类风险。改用 Unifont 后，这个问题会一起消失。

## S2 · 语义冲突与颜色漂移

### S2-1　同一位领主有四到六种颜色　〔图 02〕

七柱颜色在 5 个地方各写了一份，彼此已经不一致：

| 来源 | 内容 | 典型漂移 |
| --- | --- | --- |
| `add_pact.PILLARS` | 深色（最早的定义） | 基准 |
| `polish_demon_names.DEMON_COLOURS` | 深色的拷贝 | 与基准一致 |
| `add_demon_minions.LORDS` | `base` 与 `light` | 亚巴顿 `#5B5B62`、别西卜 `#596B18`、贝利尔 `#57256B`、玛门 `#987B08`，四柱的底色与基准不同 |
| 罪器生成器（`add_lucifer` 等） | `[DEVIL]` 前缀色 | 利维坦 `#123E7C`、萨麦尔 `#B00057`、贝利尔 `#660099`；亚巴顿与别西卜仍是作者的通用灰 `#999999` |
| `add_pact`、`add_ritual_phase2` 粒子 | 浮点三元组 | 另一套亮色：`#30D97D`、`#3DA8E8`、`#E34C4C`…… |
| `emit_guide.on_dark()` | 运行时推算的亮色 | 与以上都不同 |

玩家看到的结果是：萨麦尔的罪器前缀是洋红色，契约书前缀是棕红色，招式粒子是正红色。

### S2-2　不同意思撞了同一种颜色

- **利维坦亮色 `#62D9E8` = 新约权柄青 `#62D9E8`**，完全相同（`add_demon_minions` 中利维坦罪仆的亮色）。
- **玛门亮色 `#FFD85A` = 圣金 `HOLY` `#FFD85A`**，完全相同。贪婪与神圣共用一种颜色。
- **`[驱魔]` 用 `#FFD700`，而驱魔系统的其余 UI 用圣金 `#FFD85A`**，同一个意思有两种金色。`[驱魔]` 的 `#FFD700` 又和 `[LTD]` 的 `#FFD700` 一样。
- **`#FF3300`** 既是 `[HOLY]` 档次色，又是 `rpg_ui_style.RED`，后者被当作危险、失败的提示色：遗物临界警告和压制代价（`add_seal_relic.py:147`、`:281`）、封印 CRIT 档（`:523`）、`解约`（`add_divine_covenants.py:106`）、`毁约`（`add_pact.py:406`）、`[满魔化]`（`add_exorcism.py:959`）。

### S2-3　色板没有被真正当作唯一来源

- 产物中的文字 Hex 有 **122 种**。`_tools` 下 30 个带 Hex 的生成器里，只有 **4 个**导入了 `rpg_ui_style.py`。
- 近似色重复定义，例如 `#FF6B5E`、`#FF665E`、`#FF7A70`、`#FF806B` 是四种几乎相同的红；`#E8F4FF`、`#E8F8FF`、`#F2FDFF`、`#F3FDFF` 是四种几乎相同的白。
- `dust` 粒子色有 **150 种**，全部是生成器里的浮点字面量。

### S2-4　粒子

- 萨麦尔、贝利尔的招式和道具粒子仍在用作者旧色 `#B00057`、`#660099`，与契约表不一致。
- 11 处粒子用纯黑 `#000000`（多为渐变暗端），夜间与背景融为一体。
- 单色深色粒子（`#002E12`、`#05172E`、`#14141A` 等）在世界中几乎看不见，白白占用粒子预算。

## S3 · 语法混用

### S3-1　前缀中英混用　〔图 01〕

| 档次 | 产物中出现的写法 |
| --- | --- |
| 传说 | `[legend]` 20 件、`[传说]` 1 件（熔火之锤） |
| 史诗 | `[epic]` 18 件、`[史诗]` 1 件（晶啸） |
| 勇者 | `[brave]` |
| 限定 | `[LTD]`（由 `opt_misc.py` 从 `[限定传说]` 改写而来） |
| 恶魔 | `[DEVIL]` |
| 神圣 | `[HOLY]` |
| 类目 | `[契约]`、`[驱魔]`、`[秘仪]`、`[源质]`、`[档案]`（中文） |
| 材料 | `[🧪]`、`[🗡]`、`[item]` |

同一档出现中英两种写法，大写和小写的英文标签也混在一起。后来新增的系统全部用中文。

### S3-2　本名颜色靠运气　〔图 01「高山之啸」〕

- 有 **15 件**传说和史诗装备的本名没有写颜色（高山之啸、大地之脊、如意金箍棒、剧毒之牙、风骨、圣荆棘冠、都灵裹尸布、王者重装、不朽之膝、执行者长靴、荆棘王冠和冰霜四件）。按原版规则，附魔过的普通物品稀有度会升到 rare，本名就显示成**青色**，与 `[brave]` 同色。另有天启星、信仰之源、存续之源会显示成黄色。〔需实机确认〕
- 写了颜色的本名在同一档里五花八门：`light_purple`、`green`、`aqua`、`yellow`、`red` 都有。
- 罪器本名统一为 `#55FFFF` 青色，契约书本名是白色，上位契约本名也是白色。

### S3-3　Lore 层级

- 有整句加粗的情况（熔火之锤的题记、朗基努斯之枪的第二行），破坏了「只有名词加粗」的规则。
- 一件限定武器（樱怒之日）的 Lore 是一整段英文歌词引文，与全中文的包不协调。这段引文还可能涉及版权，建议改成原创中文题记。图 01 刻意没有收录这件物品。

## S4 · 贴图规格　〔图 04、图 05〕

### S4-1　十二种像素密度

物品栏会把贴图拉伸到同一个格子里，所以画布边长直接决定像素粗细。现状共有 **12 种原生网格**：12、15、16、17、19、20、21、24、25、26、27、32。像素尺寸从原版的 0.59 倍到 1.33 倍不等。

| 类别 | 内容 | 数量 | 处理 |
| --- | --- | --- | --- |
| **A** 作者原画·自定网格 | `_orig_rp` 原样带来的 king_sword 25、frost_scythe 27、jailors_scythe 26、katana 20、burst_gale_bow 21（4 帧）、sakura_sword 21、whispering_spear 21、warrior_sword 19、nightmares_bite 19、cutlass 17、sponge_striker 17、chill_gale_knife 15、rooted_poppy 15、frost_slayer 24 | 17 张 | **只报告**。作者的原画不重采样（决策 D5） |
| **B** 构建裁剪造成 | `fix_art.py` 按包围盒裁剪：baby_crossbow 32→**12**（6 帧，像素变粗 1.33 倍）、vine_whip 32→17（2 帧）、truthseeker 32→21；`import_art.py`：mammon_bow 32→19（4 帧） | 13 张 | **可修**。裁剪框向上取整到 16 或 32，补透明边，不缩放 |
| **C** 仅存储放大 | pact_* ×7（128，原生 16）、old_covenant（128，原生 16）、true_cross（128，原生 16）、dawn（32，原生 16）、new_covenant（192，原生 16 加噪点） | 11 张 | 视觉无差别，按原生网格存储即可 |
| **D** 非像素画离群 | soul_hunter_crossbow（6 帧，每帧 25–54 个半透明抗锯齿像素）、`a/b/c/d/s` 字母图腾（120+ 色、半透明、模糊） | 11 张 | soul_hunter 是作者原画，修正前要拿对比图给作者看；字母图腾在保留的数据包里已无发放，是孤儿资源 |

### S4-2　光源与朝向

抽查了全部武器贴图：手持类都是握柄在左下、尖端在右上，与原版一致，高光大多在左上。用「左上半区与右下半区的亮度差」做量化时，结果受弓、鞭这类造型影响很大，不能作为依据。**未发现系统性的反向光源。**

### S4-3　已确认没有问题

- **手持变换**：`fix_display.py` 已把七套手持变换统一为等比缩放，握点不变，没有剪切变形。
- **契约书七本**：统一是 16 网格书本造型，封皮主色取柱色，金属包角一致。新约、旧约与它们是同一套造型语言。
- **刻印**：神圣刻印的受难红渐变与 `[HOLY]` 同色系；22.2 节的逐件着色保留了原画的明暗。
- **符文与符石**：从作者的卷轴图和晶石图按强调色重新着色，形状统一，同类的辨识度足够。

## S5 · 图鉴与游戏内不一致

| 令牌 | 图鉴 | 游戏内 |
| --- | --- | --- |
| `--r-devil` | `#DC6A62`（偏红） | 灰色或各柱色 |
| `--r-brave` | `#57C6D6` | `aqua` `#55FFFF` |
| `--r-epic` | `#A275DE` | `dark_purple` `#AA00AA` |
| `--r-legend` | `#D9A02B` | `gold` `#FFAA00` |
| 七柱 | `on_dark()` 运行时推算 | 深色写字 |

物品图标放在 46px 框里，内边距 6px，实际按 34px 绘制，也就是 16 网格的 **2.125 倍**。像素粗细不均，一半的像素行比另一半宽一个屏幕像素。

图鉴版式本身（Cinzel、Noto Serif SC、深色典籍调）质量很高，**建议保留**，只把颜色接到同一张表上。
